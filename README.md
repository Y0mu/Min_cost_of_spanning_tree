# Directed Minimum Spanning Arborescence in C

Реализация трёх версий алгоритма Эдмондса для поиска минимального остовного ориентированного дерева (минимального разветвления). Проект реализован на чистом C11 с фокусом на сравнение различных структур данных и их влияния на производительность алгоритма.

## Описание задачи

Задача минимального остовного ориентированного дерева (Directed Minimum Spanning Arborescence, DMSA или же Minimum Cost Arborescence) ставится так:

Дан направленный граф `G = (V, E)` с неотрицательными весами рёбер и корневая вершина `r`. Необходимо найти остовное дерево, ориентированное от корня, с минимальной суммой весов рёбер. Каждая вершина кроме корня должна иметь ровно одно входящее ребро.

Это отличается от обычного минимального остовного дерева (которое неориентировано) и требует более сложного алгоритма.

## Реализованные версии

### 1. Naive Edmonds (`dmst_edmonds_naive`)

Прямолинейная реализация алгоритма Эдмондса для обучения:
- На каждой итерации для каждой вершины (кроме корня) выбирается входящее ребро минимального веса
- Если выбранные рёбра образуют цикл, он контрактуется в одну суперверину
- Процесс повторяется до получения дерева
- На каждую итерацию требуется полный проход по всем рёбрам для каждой вершины

**Временная сложность:** `O(n * m)` в худшем случае  
**Пространственная сложность:** `O(n + m)`  
**Применение:** Обучение, верификация, небольшие графы

### 2. Heap-based Tarjan/Camerini (`dmst_tarjan_heap`)

Оптимизированная версия с использованием бинарной кучи:
- Для каждой вершины хранится куча входящих рёбер, отсортированных по весу
- На каждой итерации выбор минимального входящего ребра выполняется за `O(log n)` вместо `O(m)`
- При контракции цикла в суперверину кучи её вершин сливаются (merge)
- Поддерживает глобальное добавление значений к весам рёбер (операция `heap_add_all`)

**Временная сложность:** `O(m log n)` в практических случаях  
**Пространственная сложность:** `O(m + n)`  
**Применение:** Большинство графов среднего и большого размера

### 3. Fibonacci Heap Variant (`dmst_tarjan_fib`)

Продвинутая версия с Фибоначчевой кучей:
- Фибоначчева куча обеспечивает амортизированный `O(1)` для операций `push` и `merge`, `O(log n)` для `pop`
- В алгоритме выполняется `m` операций `push` и `n log n` операций `pop`
- Операция слияния куч при контракции выполняется за `O(1)` амортизированно
- Реализует ленивую стратегию — минимальное поддерживается неявно, коррекция выполняется при извлечении

**Временная сложность:** `O(m + n log n)` амортизированно  
**Пространственная сложность:** `O(m + n)`  
**Применение:** Очень большие графы, критичные по времени исполнения

## Структура данных

### Edge (определено в `heap.h`)

```c
typedef struct Edge {
    int u;        // исходящая вершина
    int v;        // целевая вершина
    long long w;  // вес ребра
    int id;       // исходный индекс ребра во входном массиве
} Edge;
```

### Heap (интерфейс в `heap.h`)

Абстрактный интерфейс кучи с двумя реализациями:

```c
Heap *heap_create(HeapType type);           // создание (BINARY или FIBONACCI)
void heap_push(Heap *heap, int id, long long key);  // добавление элемента
int heap_top(const Heap *heap, long long *key_out); // получение минимума
int heap_pop(Heap *heap, long long *key_out);       // удаление минимума
void heap_add_all(Heap *heap, long long delta);     // добавить ко всем ключам
Heap *heap_merge(Heap *a, Heap *b);               // слияние двух куч
```

## Использование

### Сборка

```bash
make
```

Требования: GCC (или совместимый компилятор), C11. Флаги компиляции:
- `-O2` — оптимизация уровня 2
- `-std=c11` — стандарт C11
- `-Wall -Wextra -pedantic` — строгие предупреждения

Результат: исполняемый файл `dmst` в корневой директории

### Запуск

#### Интерактивное меню (по умолчанию читает `sample.txt`):
```bash
./dmst
```

#### Чтение из конкретного файла:
```bash
./dmst input.txt
```

#### Генерация случайного теста:
```bash
./dmst -r
```

#### Поведение на Windows
На Windows программа ждёт нажатия клавиши перед выходом, чтобы пользователь успел увидеть результат.

### Входной формат

**Строка 1:** `n m root`
- `n` — количество вершин (0-индексированы от 0 до n-1)
- `m` — количество направленных рёбер
- `root` — индекс корневой вершины (0-based)

**Строки 2..m+1:** `u v w`
- `u` — исходящая вершина
- `v` — целевая вершина
- `w` — вес ребра (целое число)

#### Пример (`sample.txt`):
```
4 5 0
0 1 1
0 2 5
1 2 1
1 3 3
2 3 1
```

Граф из 4 вершин, 5 рёбер, корень — вершина 0.

### Выходной формат

Программа выполняет три версии алгоритма и выводит для каждой:
1. Найденная минимальная стоимость (или сообщение об ошибке, если граф не связен от корня)
2. Время выполнения в секундах
3. На стандартный вывод информация о прохождении каждой версии

## Проверка входных данных

Перед запуском алгоритма программа проверяет достижимость всех вершин из корня:

```c
long long check_reachable(int n, int root, int m, const Edge *edges);
```

Выполняет BFS от корня:
- Если из корня достижима все вершины графа, возвращает 1 (true)
- Если найдена недостижимая вершина, выводит ошибку и завершает работу
- Это необходимо, так как минимальное остовное ориентированное дерево существует только если граф сильно связен или граф направлен так, что все вершины достижимы из корня

## Модули проекта

### `main.c`
Точка входа, обработка аргументов командной строки:
- Парсинг входного файла или генерация случайного графа
- Инициализация структур данных
- Вызов всех трёх версий алгоритма с замером времени
- Вывод результатов

### `dmst.c / dmst.h`
Основная реализация:
- `check_reachable()` — проверка достижимости вершин BFS
- `dmst_edmonds_naive()` — наивная версия
- `dmst_tarjan_heap()` — версия с бинарной кучей
- `dmst_tarjan_fib()` — версия с Фибоначчевой кучей
- Вспомогательные функции для работы с циклами и сокращением графа

### `heap.c / heap.h`
Интерфейс и фабрика для куч:
- Выбор реализации по типу `HeapType`
- Делегирование вызовов в соответствующую реализацию

### `fibheap.c / fibheap.h`
Полная реализация Фибоначчевой кучи:
- Структура данных с потенциал-функцией
- Операции `insert`, `min`, `extract_min`, `decrease_key`
- Адаптирована для работы с весами рёбер (целые числа)

### `unionfind.c / unionfind.h`
Структура Union-Find для обнаружения циклов:
- Используется для отслеживания компонент связности при сокращении графа
- Реализация с полусжатием пути (path halving) для эффективности

## Алгоритмические детали

### Основной цикл Эдмондса

1. **Выбор минимальных входящих рёбер:** Для каждой вершины `v ≠ root` выбирается входящее ребро с минимальным весом в текущем графе
2. **Обнаружение цикла:** Если выбранные рёбра образуют цикл, текущая вершина помечается как посещённая
3. **Сокращение графа:** Цикл сокращается в единственную суперверину
4. **Повтор:** Процесс повторяется для сокращённого графа

### Различие в реализациях

| Аспект | Naive | Heap | Fibonacci |
|--------|-------|------|-----------|
| **Выбор мин. входящего ребра** | Полный перебор `O(m)` | Куча `O(log n)` per pop | Куча `O(1)` амортизировано per pop |
| **Слияние куч** | Пересоздание `O(m)` | Merge `O(m)` | Merge `O(1)` амортизировано |
| **Глобальное смещение весов** | Добавление к каждому `O(m)` | `heap_add_all` `O(1)` | `heap_add_all` `O(1)` |
| **Цикл контракции** | Поиск цикла `O(n²)` | Поиск цикла `O(n²)` | Поиск цикла `O(n²)` |

### Коррекция весов при сокращении

При сокращении цикла `C`:
1. Для каждого ребра `e` входящего в вершину в цикле из вне: скорректировать вес
2. Стоимость сокращения: `sum(edge.w for edge in selected_edges[C]) - edge.w`, где `edge` — входящее из вне

## Примечания реализации

- **Переполнение:** Весы ребер хранятся как `long long` для работы с большими графами
- **Динамическое распределение:** Все структуры выделяются динамически, освобождаются при ошибках
- **Платформа:** Windows (консоль UTF-8)
- **Тестирование:** Включен режим генерации случайных графов (`dmst -r`)

## Проверка корректности

1. На `sample.txt` все три версии должны выдать одинаковый результат
2. Для графа без циклов все версии работают за O(n)
3. На случайных графах версии отличаются только временем выполнения
